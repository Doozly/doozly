Deploying Doozly

For IT admins. Last updated 23 November 2026

The short version. Every installer installs, upgrades and uninstalls without a prompt. A small policy file switches off the built-in updater and sets the defaults. Doozly can only see its own folder in each user's OneDrive, Google Drive or Dropbox, and there is no Doozly server holding any task data.

Installers

All installers are on the latest release. Replace <version> below with its version number, like 0.1.0.

SystemFor managed installsFor one person
Windows 10 and 11 (x64)Doozly_<version>_x64_en-US.msiDoozly_<version>_x64-setup.exe
macOS (Apple silicon)Doozly_<version>_aarch64.pkgDoozly_<version>_aarch64.dmg
macOS (Intel)Doozly_<version>_x64.pkgDoozly_<version>_x64.dmg

The installers are not code signed. Installed by a management tool they run without a warning. Installed by hand, Windows and macOS warn once on the first start, see the readme. Some tools only take signed packages, like Intune for macOS line-of-business apps, and can't deploy the macOS package.

Windows

The MSI installs per machine to C:\Program Files\Doozly and doesn't start Doozly afterwards.

msiexec /i Doozly_<version>_x64_en-US.msi /qn /norestart
msiexec /x Doozly_<version>_x64_en-US.msi /qn /norestart

Installing a newer MSI over an older one upgrades it. In Intune, add it as a line-of-business app or a Win32 app with these commands. Doozly needs the Microsoft Edge WebView2 runtime. Windows 11 and an up-to-date Windows 10 have it already, otherwise the MSI downloads it silently. On networks without internet access, deploy Microsoft's WebView2 Evergreen Standalone Installer first.

macOS

The package installs Doozly to /Applications. Jamf, Kandji, Munki and other tools that take unsigned packages can deploy it as it is.

sudo installer -pkg Doozly_<version>_aarch64.pkg -target /
sudo rm -rf /Applications/Doozly.app && sudo pkgutil --forget app.doozly.desktop

Linux

The deb and rpm declare their dependencies (WebKitGTK 4.1, GTK 3, libayatana-appindicator), so the package manager installs them too.

sudo apt-get install -y ./Doozly_<version>_amd64.deb
sudo apt-get remove -y doozly

sudo dnf install -y ./Doozly-<version>-1.x86_64.rpm
sudo dnf remove -y doozly

With Ansible:

- name: Doozly (Debian, Ubuntu)
  ansible.builtin.apt:
    deb: https://github.com/Doozly/doozly/releases/download/v<version>/Doozly_<version>_amd64.deb

- name: Doozly (Fedora, RHEL)
  ansible.builtin.dnf:
    name: https://github.com/Doozly/doozly/releases/download/v<version>/Doozly-<version>-1.x86_64.rpm
    disable_gpg_check: true

The policy file

Put a policy.json in this place, readable by everyone:

  • Windows: C:\ProgramData\Doozly\policy.json
  • macOS: /Library/Application Support/Doozly/policy.json
  • Linux: /etc/doozly/policy.json
{
  "updates": false,
  "openAtLogin": true,
  "closeToTray": true,
  "quickAdd": false
}
KeyWithout itWhat it does
updatestruefalse switches the built-in updater off for good. Users can't switch it back on.
openAtLoginfalseStarts Doozly in the tray when the user logs in.
closeToTrayfalseThe close button keeps Doozly running in the tray, so reminders still come.
quickAddtrueThe quick add box on Ctrl+Alt+N (⌥⌘N on a Mac).

Apart from updates, these are only the defaults for a user's first start. Users can change them in Settings after. A missing file is fine, and a broken one is ignored.

Updates

On its own, Doozly checks for a new version after start and then every 6 hours. It downloads it in the background and installs it when the user clicks Restart. Updates come from github.com/Doozly/doozly and must carry the project's signature, otherwise they are refused. For managed installs, set "updates": false and roll out new versions with your own tooling.

Sign-in and consent

Users sign in in their normal browser. Doozly asks only for:

  • Microsoft: Files.ReadWrite.AppFolder (its own folder Apps/Doozly in OneDrive), plus openid, profile and offline_access for the name, email and staying signed in. Work or school accounts need OneDrive in the tenant.
  • Google: drive.appdata (a hidden folder for Doozly only), plus openid, email and profile.
  • Dropbox: read and write in its app folder Apps/Doozly, plus the account's name and email.

Doozly can't see any other files. Tasks go straight from the device to the user's own storage.

Network

Behind a proxy or firewall, the desktop app needs these hosts:

  • Microsoft: login.microsoftonline.com, graph.microsoft.com, and for the files *.1drv.com, *.microsoftpersonalcontent.com, *.sharepoint.com
  • Google: accounts.google.com, oauth2.googleapis.com, www.googleapis.com
  • Dropbox: www.dropbox.com, api.dropboxapi.com, content.dropboxapi.com
  • Updates: github.com, objects.githubusercontent.com

The sign-in comes back to the app on the computer itself (localhost). For Dropbox that's on port 38471, 38472 or 38473. Nothing else listens, and the desktop app needs no Doozly server.

Where Doozly keeps things

  • Tasks and settings: in the user's profile, under app.doozly.desktop. On Windows in %APPDATA% and %LOCALAPPDATA%, on macOS in ~/Library/Application Support and ~/Library/WebKit, on Linux in ~/.config and ~/.local/share.
  • Sign-in: the refresh token in the system's credential store (Credential Manager, Keychain, Secret Service), under app.doozly.desktop.

Uninstalling leaves these in place, like most apps do. Delete them too for a clean removal. The synced copy stays in the user's own storage.
